My University of Denver coursework spans retail analytics, credit risk and database design. These projects show how I use R and SQL to answer business questions and organize the records behind them.

Where should a retailer focus its attention?

I joined transaction, customer and product tables to compare revenue over time and profit by device. Mobile generated the most total profit in the case dataset. That gave me a reason to recommend reviewing the mobile shopping experience. The chart measures total contribution, so it leaves open whether the advantage comes from more orders or more profit per order.

A second challenge was deciding how finely to segment customers. I standardized recency, frequency and monetary value before fitting k-means models with two through six clusters. Improvement tapered after four clusters. Four gave me a manageable set of groups for comparing repeat purchasing and identifying customers to re-engage.

When does a loan-risk model miss a default?

For a credit union case study, I compared statistical learning methods on 3,357 complete application records. Only 924 records (27.5%) were labeled bad risk. With that imbalance, a single accuracy number could hide the mistakes a lender cares about most.

I reviewed three held-out cases that logistic regression classified as good risk despite their bad-risk labels. All three lacked a previous default. Prior default history was informative across the dataset, yet these cases showed how a reviewer could miss risk by relying on that signal alone. My recommendation for the case was to examine debt, assets, income and expenses alongside credit history.

How do you track a unit that changes from mission to mission?

INFO 3140 · Winter 2026 · SQL

For my database design final, I chose the clone army from Star Wars. Each trooper belongs to one unit, but a mission can involve many troopers, and a trooper can serve on many missions. Those two rules called for different structures.

I drew an entity–relationship diagram, documented the functional dependencies and wrote SQL to create five tables. I stored the unit identifier on the trooper record. For missions, I created a separate assignment table with a two-column primary key. That lets a planner look up a mission roster or a trooper’s mission history from the same records, while preventing duplicate assignments.

Read the assignment-table SQL from my final project
CREATE TABLE CLONE_MISSION (
CloneID INT NOT NULL,
MissionID INT NOT NULL,
CONSTRAINT PK_CLONE_MISSION PRIMARY KEY (CloneID, MissionID),
CONSTRAINT FK_CM_CLONE FOREIGN KEY (CloneID)
REFERENCES CLONE(CloneID),
CONSTRAINT FK_CM_MISSION FOREIGN KEY (MissionID)
REFERENCES MISSION(MissionID));

Giving users a way into a database

INFO 3240 · Spring 2026 · Database application

In a separate database application project, I submitted video demonstrations of forms and reports. The forms portion asked me to explain who would use each form and what task it supported. The final demonstration covered a startup form, a tabular report and a matrix report.

The two report formats answer different questions. A tabular report lets a user inspect individual records. A matrix report arranges values across rows and columns so a user can compare groups at a glance.
